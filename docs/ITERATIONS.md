# 持续体验迭代记录

这份文件记录首版功能完成后的每一轮产品迭代。每轮遵循同一个闭环：

1. **体验功能**：以真实任务走完关键路径，记录卡顿、犹豫、错误与无效操作。
2. **思考优化**：区分功能缺失、信息架构、交互反馈、视觉层级、性能和可靠性问题。
3. **写迭代产品稿**：明确用户场景、问题证据、设计决策、验收标准与不做事项。
4. **开发**：小步实现，数据迁移向后兼容，不牺牲本地隐私边界。
5. **测试**：静态检查、构建、接口、持久化、异常路径、键盘和响应式回归。

完成第五步后立即回到第一步。只有通过验收的改动才进入 Git 检查点。

## 迭代 0 · 完整首版基线

### 用户场景

- 用户希望用一套私人、本地运行的工具管理完整求职过程，并保存可复盘的面经。
- 用户希望从英文文章和播客的真实语境中学习词汇，英文解释优先，必要时再看中文。
- AI 只在主动触发时参与，密钥由服务器侧环境变量管理；所有核心功能在 AI 不可用时仍可使用。

### 设计决策

- 两款应用拥有完全独立的视觉系统和数据库，入口页保持中性。
- SQLite 运行在专用 Worker，并使用浏览器 OPFS；大文件不写进 SQLite。
- LinkedIn 与 BOSS 采用原链接、分享文本、CSV 和浏览器采集器，不模拟登录或绕过平台限制。
- 播客优先接受带字幕内容与本地字幕导入；自动转录作为独立、可选的兼容端点。

### 首版验收线

- 职迹：职位、阶段、任务、日历、面试/面经、人脉、材料、数据与设置主路径完整可用。
- 拾词：文章/RSS/播客/字幕导入、上下文选择、AI 解释、词库、间隔复习、统计和设置完整可用。
- 刷新与重启后数据仍在；两款应用数据互不影响；可导出并恢复备份。
- API 密钥不进入浏览器数据库、导出文件、日志或 Git。
- lint、类型检查、生产构建和关键自动化测试全部通过。

### 完成状态

进行中。首版达到验收线后开始记录迭代 1。

## 迭代 1 · 职迹首次启动可靠性

### 体验证据

- 任务：从套件首页点击“职迹”，等待首次本地数据库初始化。
- 观察：页面进入阻断状态；SQLite Worker 被 vinext 的客户端模块运行时解析为 `file://` 地址，浏览器因来源不同拒绝启动。
- 影响：静态构建和服务端首屏均可通过，但真实浏览器无法打开任何求职数据，是所有后续体验的最高优先级阻断。

### 迭代产品稿

- 目标：无论开发构建还是生产构建，数据库 Worker 都必须从当前 `http://localhost:3000` 来源加载；首次打开可完成建表和示例数据写入。
- 方案：保留 Vite 对静态 Worker URL 的打包识别，并在 vinext 暴露文件协议 URL 时，使用其已生成的 pathname/search 在浏览器当前来源上重建 URL。
- 验收标准：`crossOriginIsolated === true`；职迹首次打开进入主界面；Worker URL 为同源 HTTP；刷新后数据仍存在；控制台无 Worker/SQLite 错误；生产构建继续通过。
- 本轮不做：不在可靠性未通过前调整看板或视觉细节。

### 开发与验证

- 改动：在保留 Vite Worker 静态打包识别的同时，将 vinext 暴露的 `file://` Worker 地址重建为当前页面同源 URL；SQLite Worker 仅在参数非空时执行 `bind()`，避免无占位符语句在首次建表时中断。
- 测试：真实浏览器完成首次建表与种子写入；首页显示 6 个活跃机会、4 个待办和 1 场面试；完成一项待办后刷新，剩余 3 项状态保持；浏览器控制台无错误或警告。SQLite Worker 成功启用依赖 `SharedArrayBuffer`，结合运行时 COOP/COEP 响应头验证隔离前提已满足。
- 结果：通过。开发环境中的 Worker 同源启动、首次初始化与刷新持久化主路径恢复。
- 下一轮候选：完成事项缺少清晰的回看/撤销入口；主界面信息密度、首要动作、字号与对比度需要视觉专项审计。

## 迭代 2 · 不给求职者打分

### 体验证据

- 任务：打开职迹首页和分析页，判断自己今天应该做什么。
- 观察：首页把“有效回复率”作为四个核心数字之一；分析页继续展示“面试转化”“Offer 率”“待办完成率”和渠道推进率；侧栏还用“本周投递 1 / 8”呈现固定目标。
- 用户反馈：当暂时收不到 Offer 时，这类结果率不是帮助，而是反复提醒失落、制造压力。功能越多、数字越多，并不等于体验越好。
- 影响：产品把不可完全控制的招聘结果包装成个人成绩，让原本用于减轻负担的私人工作台增加了情绪成本。

### 迭代产品稿

- 目标：职迹只帮助用户看清可控的下一步、等待状态与可沉淀的经验，不把 Offer、面试或任务完成情况变成评分。
- 方案：首页用“等待回应”替代任何比率；侧栏删除固定投递目标，改为不设目标的近期记录；“求职分析”改为“过程回顾”，默认只展示正在推进、等待回应、已安排下一步和已写面经的数量。来源模块只说明记录分布，不评价渠道优劣；结束阶段不进入默认图表。
- 情绪成本审查：每个统计必须回答“它会改变哪个可控决定”；无法回答，或主要作用是比较、催促、评判时，不展示。空状态和提醒避免“落后”“失败”“应该更多”等措辞。
- 验收标准：界面中不再出现 Offer 率、面试转化率、回复率、任务完成率或固定周投递目标；保留阶段和原始记录；分析页仍能帮助发现没有下一步的机会；所有文案在零 Offer、零面试时依然中性、尊重。
- 本轮不做：不删除任何历史数据，不隐藏用户主动打开的具体职位结果，不把温和体验等同于回避事实。

### 开发与验证

- 改动：移除首页有效回复率、分析页 Offer/面试/完成率、渠道推进率和侧栏固定周投递目标；新增“等待回应”、不设目标的近期记录，以及只呈现可控状态的“过程回顾”。默认阶段图不再展示已拒绝、已接受和已退出等结束状态。
- 测试：真实浏览器逐项检查首页与过程回顾；确认侧栏明确显示“不设目标，也不给你打分”，首页只呈现等待数量，过程回顾只呈现当前行动、下一步和面经记录；代码搜索确认旧比率和周目标文案已清除；浏览器无运行时错误。Career scoped lint 与全量类型检查通过。
- 结果：通过。Offer 等具体事实仍保留在职位记录和时间线中，但不会再被聚合成对用户的成绩。
- 下一轮候选：已完成待办的回看与恢复；Apple 风格视觉专项。

## 迭代 3 · 完成之后仍然可找回

### 体验证据

- 任务：在“今天与接下来”中勾选一条待办，然后刷新并尝试确认刚才的操作。
- 观察：任务会立即从首页和待办清单消失；刷新后状态正确保留，但界面没有撤销提示，也没有已完成列表可以核对或恢复。
- 影响：高频的一次点击带来不可见的状态变化，用户容易担心点错；“消失”也削弱了工具替用户保存过程记忆的承诺。

### 迭代产品稿

- 目标：完成动作轻快，但永远可确认、可撤销、可恢复；承认做过的事情，不把它们换算成完成率。
- 方案：每次切换待办状态后显示短时撤销提示；议程页增加默认收起的“已完成”区域，展示任务与关联职位，并允许一键恢复。
- 验收标准：首页勾选后出现“待办已完成 / 撤销”；点击撤销后任务原位恢复且刷新后仍为未完成；不撤销时可在议程的已完成区找到；恢复后回到待办清单；键盘与读屏能识别展开状态和操作名称。
- 本轮不做：不引入积分、连续天数、庆祝动效或完成率；不删除已完成记录。

### 开发与验证

- 改动：待办状态切换后显示具名的短时撤销按钮；议程新增默认收起的已完成区域，可查看关联职位并恢复；无待办时使用中性空状态。
- 测试：真实浏览器完成“未完成→完成→即时撤销→再次完成→刷新→已完成区回看→恢复”的双向链路；撤销提示和展开状态具备可访问名称；最终把测试记录恢复为原始已完成状态。刷新后仍显示 3 个未完成与 1 个已完成，浏览器无错误；Career scoped lint 与全量类型检查通过。
- 结果：通过。完成不再等于消失，也没有引入完成率或奖励机制。
- 下一轮候选：Apple 风格视觉专项。

## 迭代 4 · 职迹 Apple 风格视觉专项

### 体验证据

- 任务：在 390px 移动视口与桌面结构中扫描今日、议程和过程回顾，判断是否能从容地看清首要信息并可靠操作。
- 观察：绿色/米白、圆角和留白已有克制基础，但 158 个显式字号中 129 个不超过 11px；弱文字对比度约 2.86:1；按钮、勾选框和图标操作普遍偏小。巨大标题与微型正文之间缺少稳定中层，卡片、边框和徽章层层嵌套，整体更像微缩 BI 面板。
- 影响：页面第一眼有精致感，但需要费力辨认；移动端输入可能触发 iOS 自动放大，键盘焦点也不够清楚。“高级”停留在装饰，而没有落实为清晰、安静和可信赖。

### 迭代产品稿

- 目标：建立接近 Apple 产品界面的从容层级——内容先于容器，清晰先于密度，动效服务于方位感；保持职迹自己的深绿身份，不复制 Apple 商标或具体界面。
- 视觉语言：使用系统字体与五级字阶；正文不小于 13–14px、元数据不小于 12px、移动表单 16px；页面背景改为中性浅灰，白色表面只保留两级层次；统一 16–22px 圆角、发丝分隔线和低不透明度阴影。
- 交互语言：主要按钮和移动触控目标 44px；所有原生与自定义控件使用高对比焦点环；窄屏关闭侧栏不能进入 Tab 顺序；安全区和动态视口正确预留；Reduce Motion 下停止位移动画与旋转。
- 情绪成本审查：视觉强调只给“下一步”和正在编辑的对象，不用红色、徽章、进度条或动效催促投递数量。
- 验收标准：无 UI 文本小于 12px；正文/弱文字达到 4.5:1，焦点态达到 3:1；移动表单不缩放；390px 页面无非预期横向滚动；底栏按钮在安全区内仍有 44px；今日、议程和过程回顾截图能按标题→下一步→辅助信息自然扫描。
- 本轮分段：先完成字阶、对比度、触控与表面层级；随后单独处理弹层焦点模型、键盘看板和移动职位列表，避免一次重构引入不可定位的回归。

### 开发与验证

- 改动：重建深绿 + 中性浅灰的表面系统与系统字体字阶；所有显式 UI 字号提升至至少 12px，正文和关键操作为 13–16px；增强弱文字与焦点环对比度；按钮、导航、搜索、筛选和移动底栏扩大至 40–56px；卡片统一更从容的圆角、留白和轻阴影。首页把“最重要的一步”移到统计卡之前；移动端修复动态视口、安全区、侧栏关闭后仍可聚焦、表单自动放大、任务列挤压和 Reduce Motion。
- 测试：390px 真实页面截图复核今日与议程，1440×900 复核桌面首屏，800px 验证图标导航仍有中文可访问名称，测试后恢复用户原视口；代码扫描确认无小于 12px 的显式字号；`#68716c` 弱文字在白底/页面底分别为 5.04:1/4.63:1，`#087a55` 焦点色分别为 5.35:1/4.91:1；浏览器无错误或警告。Career scoped lint 与全量类型检查通过。
- 结果：本阶段通过。页面扫描顺序已从“问候→统计成绩”变为“问候→下一步→辅助统计”，视觉更安静且可读。
- 下一轮候选：弹层焦点圈定与移动端职位卡片。

## 迭代 5 · 弹层像系统界面一样可靠

### 体验证据

- 任务：仅用键盘打开“记录职位”、职位抽屉、面经抽屉和全局搜索，再尝试 Tab、Shift+Tab、Escape 与关闭后继续操作。
- 观察：弹层有视觉遮罩，但缺少可访问名称、初始焦点、焦点圈定、背景禁用和触发器焦点归还；Escape 只关闭部分状态，职位/面经抽屉不响应。搜索面板还展示了未实现的方向键提示。
- 影响：视觉上像系统弹层，行为上却不可信；键盘与读屏用户可能“掉到”背景页面，关闭后也不知道焦点去了哪里。

### 迭代产品稿

- 目标：Modal、Drawer 与搜索面板统一遵循系统弹层心智模型：有名字、打开即进入、焦点不逃逸、Escape 可关闭、关闭回原处。
- 方案：建立共享弹层可访问性钩子；记录触发器，给背景兄弟节点设置 inert，锁定页面滚动，聚焦第一个可编辑控件，圈定 Tab，并在卸载后恢复背景与焦点。每种弹层通过 `aria-labelledby` 或 `aria-label` 命名；删除搜索面板未实现的键盘承诺。
- 验收标准：真实浏览器打开各类弹层后 active focus 位于弹层内；连续 Tab/Shift+Tab 不进入背景；Escape 可关闭；关闭后焦点回触发器；DOM 中所有 dialog 均有名称，关闭按钮和遮罩有操作名称；嵌套 AI 预览不会错误解锁其后的职位抽屉。
- 本轮不做：不在本轮重做弹层内容结构，也不引入第三方组件库。

### 开发与验证

- 改动：新增共享弹层可访问性钩子，统一初始焦点、Tab/Shift+Tab 圈定、Escape、背景 inert、滚动锁定和焦点归还；Modal 使用标题/说明 ID 命名，Drawer 与全局搜索使用具体标签；补齐遮罩、关闭、阶段、面经问题输入和删除按钮名称；删除全局搜索未实现的方向键/回车提示。
- 测试：真实浏览器验证“记录职位”打开后公司输入自动聚焦，首尾 Tab 双向循环，Escape 关闭并回到原“记录职位”按钮；职位抽屉以公司/职位命名、阶段选择自动聚焦、Escape 回到“打开职位”；全局搜索具名、输入自动聚焦并正确归还。进一步从职位抽屉调用真实 DeepSeek 匹配分析，约 10.5 秒成功返回草稿；关闭 AI 预览后职位抽屉保持打开且焦点回到“匹配度分析”，再关闭抽屉背景才恢复。浏览器无错误或警告，Career scoped lint 与全量类型检查通过。
- 结果：通过。三类弹层与嵌套 AI 场景拥有一致、可预测的系统行为。
- 下一轮候选：移动职位摘要卡与键盘看板。

## 迭代 6 · 窄屏职位摘要与等价阶段操作

### 体验证据

- 任务：在约 390px 宽度打开“全部职位”，浏览职位并更改看板阶段；随后只用键盘完成同一任务。
- 观察：移动页面仍渲染最小宽度 920px 的桌面表格，首屏只看到职位和半截阶段，必须横向拖动才能知道下一步；看板只配置 PointerSensor，职位卡还是一个包含拖动按钮的 `role=button`，键盘没有等价的阶段切换入口。
- 影响：手机上最常见的快速查看变成二维找信息；“拖起来很顺”掩盖了没有鼠标时根本无法推进职位的问题。

### 迭代产品稿

- 目标：窄屏以一张卡回答“这是什么职位、在哪个阶段、下一步是什么”，无需横滚；所有用户都能用明确控件推进阶段。
- 方案：桌面保留信息密集表格，≤760px 切换为独立职位摘要卡；筛选控件具名。看板卡片拆成非嵌套的打开按钮、拖动柄和阶段选择器；拖动保留，阶段选择器作为始终可见的键盘/触控等价路径。
- 验收标准：390px 页面本身与职位列表无横向滚动；每张卡显示职位、公司、阶段、来源、地点和下一步；点击卡片打开详情。仅键盘可聚焦任意看板卡的阶段选择器并移动到所有可见阶段，移动后刷新仍保留；卡片不再出现交互控件嵌套。
- 本轮不做：不强迫移动看板改成纵向列表；看板横向空间仍可作为明确的二维工作区。

### 开发与验证

- 改动：≤760px 隐藏桌面表格并渲染独立职位摘要卡，完整呈现阶段、来源、地点和下一步；移动筛选改为两列网格并补齐名称/pressed 状态。看板职位卡拆分为语义清晰的 article、打开按钮与拖动柄，新增具名阶段选择器作为键盘/触控等价操作；看板说明同步告知两种操作方式。

## 迭代 8 · 界面上的每一个承诺都必须是真的

### 体验证据

- 任务：从头像进入设置、切换“保留 AI 原始内容”，再生成一份 AI 草稿并尝试保留；同时核对材料定制、联系人更多按钮和备份提示的实际落位。
- 观察：头像只有“个人设置”名称却不导航；AI 原文开关点击前后 DOM、状态和样式完全不变；“已连接”是硬编码；AI 的“接受为草稿”只关闭预览并提示已保留，没有写入 SQLite、表单、剪贴板或草稿表。材料定制没有材料选择，也没有读取附件正文，却声称会保存草稿；联系人更多按钮没有动作；SQLite 备份明确不含 OPFS 附件，却提示“完整备份”。

### 迭代产品稿

- 目标：没有落位的能力不冒充“已保存”，没有实时检查的状态不冒充“已连接”，没有实现的控件不保留装饰性入口。

- 过程准确性：待进行面试只认 `scheduled`；`canceled` 进入档案并明确显示已取消，不再出现在日程、下一步或“已有下一步”里。空白复盘不显示“待复盘”欠债状态。
- 验收标准：点击头像进入设置；AI 状态来自 health 接口并能区分检查中/已配置/未配置/失败；页面没有无事件的开关、拖动柄和联系人更多按钮；AI 预览没有“接受为草稿”及虚假保存提示，复制按钮实际写入剪贴板；职位拆解结果不含 overall score；导出/恢复提示不再说完整备份； canceled 面试只出现在档案。
- 本轮不做：不在没有明确目标表结构前建立泛化 AI 草稿库；不把简历附件正文悄悄发送给模型；联系人完整编辑将在独立迭代完成。

### 开发与验证

- 改动：头像现在进入设置；AI 区实时读取 `/api/health` 并显示实际模型/已配置/未配置/失败，假原文开关与假阶段拖动柄已删除。AI 预览改为“关闭预览 / 复制结果”，复制使用 Clipboard API 并带本地选择回退，按钮本身显示复制中/已复制/失败；删除无法读取附件正文的材料定制和无事件的联系人更多按钮，无附件材料入口改成明确的“新建带附件版本”。职位“匹配度分析”改成不评分的“职位要求拆解”，服务端契约不再包含 overall score；删除职位抽屉里名实不符的“AI 下一步”。联系人最近联系可留空，不再新增即虚构“今天联系”。备份提示明确不含附件原件。

## 迭代 10 · 面经 AI 必须接住刚写下的内容

### 体验证据

- 任务：打开一条面经，在原始速记、总结或复盘中写入尚未保存的新内容，直接点击“AI 整理速记”，再尝试把结果带回当前面经。
- 观察：当前表单的 summary/raw_notes/reflection 是 uncontrolled input；AI 按钮发送的是打开抽屉时的持久化 interview 快照，只额外带了受控 questions。刚写的速记必须先保存、再重新打开才可能被模型看到。生成结果进入通用预览后也只有复制，没有回填目的地。
- 影响：用户最需要 AI 的时刻正是刚结束面试、快速倾倒记忆的时候；要求先保存再调用会打断记录，还可能让模型整理旧内容。复制 JSON 再手工拆回多个字段，比自己整理更麻烦。

### 迭代产品稿

- 目标：用户可以先自然写速记，再让 AI 基于“此刻表单里的全部内容”整理；AI 结果只填入本次尚未保存的草稿，不绕过最终确认。
- 方案：总结、原始速记、状态与复盘全部改为受控草稿；调用时发送当前 summary/raw_notes/questions/reflection。通用 AI 预览在本场景增加“填入面经草稿”，把 summary、问题、我的回答、追问/改进建议与复盘段落映射回对应字段；原始速记永远保留。
- 可逆性：填入前保存当前表单快照，显示“已填入 / 撤销整理”；撤销恢复 AI 前的未保存内容。关闭抽屉或点击取消不会写数据库；只有“保存面经”才落库。
- 验收标准：在 raw notes 加入唯一临时标记后直接调用，发送 payload 含该标记；AI 预览出现“填入面经草稿”；填入后字段可编辑且原始速记不变；撤销精确恢复；保存、刷新后结果持久化。测试完成后恢复 Figma 原始数据；浏览器无错误。
- 本轮不做：不自动猜测面试官反馈，不把 `better_answer` 当作用户真实回答，不自动将状态改为已完成。

### 开发与验证

- 改动：面试状态、总结、原始速记、问题/回答/备注与复盘全部改为受控草稿，AI 请求在点击瞬间发送当前表单快照。面经场景的 AI 预览新增明确的“填入面经草稿”，只回填总结、问题和带来源标签的复盘建议；原始速记与状态不受 AI 结果影响。已有回答永远优先保留；模型生成的 `my_answer` 只有能在原始速记中逐字找到时才可进入回答，否则只作为“AI 整理的回答候选（待确认）”进入备注，`better_answer` 始终标为“AI 改进建议”。填入前深拷贝可变字段并提供一次撤销；用户随后手改这些字段会让旧撤销失效，避免吞掉新输入。新增严格白名单解析、长度/数量上限、异常不部分回填、应用失败不关闭预览，以及 AbortController + 请求 ID 防止并发结果串线。
- 测试：新增 4 项纯函数契约测试，覆盖保留用户回答、原文依据判断、畸形/空结果拒绝、集合与文本边界；连同本地数据库契约共 8 项全部通过。真实浏览器在 Figma 面经的 status、summary、raw notes、问题与 reflection 写入 4 处未保存标记并临时选择 canceled，DeepSeek 返回同时识别标记、跨时区速记和 canceled 冲突，证明请求使用当前表单而非 SQLite 旧值。点击填入后总结/问题/复盘更新，原始速记与状态保持不变；撤销精确恢复 4 处标记。关闭不保存、重开后标记为 0 且数据库仍为 completed 原值。第二次完成“AI 填入→用户手改总结→保存→关闭重开”，确认 AI 复盘、手改总结与速记均持久化；随后逐字段恢复 Figma 原始数据并重开核对无测试标记。319×734 真实截图确认上下文说明、44px 表单控件与固定保存栏没有遮挡。Career lint、全量类型检查、8 项测试与五环境 production build 全部通过。
- 结果：通过。AI 现在接住用户刚写下的内容，但仍停留在可核对、可撤销、需手动保存的草稿边界内；模型措辞不会自动冒充用户经历。
- 下一轮候选：职迹完整附件备份；联系人详情与编辑；最终冻结前无障碍回归。

## 迭代 11 · 备份必须带走真正的材料原件

### 体验证据

- 任务：在设置中导出职迹备份，假设浏览器资料被清除，再判断能否只用这个文件恢复简历、作品集与案例附件。
- 观察：当前按钮明确只导出 SQLite；材料表里的名称、版本与 `file_key` 会被带走，但 OPFS 中的实际字节不会进入备份。恢复后界面仍可能显示“本地附件”，点击时却找不到原件。
- 影响：诚实提示避免了虚假安全感，但仍把最关键的恢复工作留给用户手工完成。对私人本地应用而言，浏览器资料清除正是最需要备份的时刻；只有索引而没有原件的材料记录不算完整恢复。

### 迭代产品稿

- 目标：一个 Career 备份文件同时包含 SQLite 与所有被材料记录引用的 OPFS 原件；导出前逐个校验，恢复前完整验证，任何损坏都不能覆盖现有数据。
- 格式：使用版本化的 `.career-backup` 二进制容器：固定魔数、受限长度的 JSON manifest、SQLite 字节和顺序附件字节。manifest 记录产品/版本、导出时间、SQLite application ID / user version，以及数据库和每个附件的 byte size、SHA-256 与原始元数据；manifest 自身也有基于固定投影的 SHA-256，不包含 API key、模型日志或隐藏状态。
- 导出：只收集数据库中真实引用的 Career 附件；缺失、大小不符或 hash 不符时整体失败并指出问题，不生成“成功”文件。文件是明文备份，界面明确建议安全保管。
- 恢复：先限制格式/数量/大小，再完整验证 SQLite 头、身份、manifest 与每段 SHA-256；验证全部通过后把附件以新 UUID 流式写入暂存，把数据库写入不可变 candidate generation，并在 candidate 的单一事务中校验材料行与 manifest 后重写引用。candidate 关闭重开并通过完整性、外键、必需表列、trigger/view 白名单及 canonical identity 后，才写入带序号和 checksum 的 A/B 活动指针。切换前 live generation 从不被覆盖；成功后暂时保留上一代数据库与原附件作安全回退。旧版 `.sqlite3` 也走 candidate 路径，并清空没有原件可恢复的附件索引。
- 跨标签页：所有 Career 读写、材料文件操作、导出与恢复共同参与同一 Web Lock；代际切换通过 BroadcastChannel 通知其它标签页重载，避免旧连接继续写入上一代数据库。浏览器不支持 Web Locks 时拒绝执行完整备份，不静默降级成不一致快照。
- 验收标准：无附件也能导出合法完整备份；带多个 Unicode 文件名附件时 round-trip 后内容 hash、MIME、名称和材料关联一致；篡改 manifest、数据库或任一附件都会在覆盖前失败；在 candidate 写入、校验与指针切换前后的失败结果只能是全旧或全新；备份不含 DeepSeek key；移动端可看懂“完整备份 / 旧版 SQLite”的区别。
- 本轮不做：不把明文附件发往服务器；不以尚未经过密码学与大文件测试的自制加密冒充“加密备份”；跨三个应用的总套件备份留到各产品格式稳定后。

### 开发与验证

- 改动：新增带固定魔数、严格 manifest、manifest 自身摘要、SQLite 身份与逐段 SHA-256 的 `.career-backup` 容器；导出只打包数据库真实引用且元数据完全一致的材料原件。Career 数据库与文件操作统一进入 Web Lock，恢复先把附件写入新 UUID，再把数据库写入不可变 generation；附件引用校验与映射在 candidate 的单一事务中完成。Worker 新增 READY/token/hash、关闭重开复检、历史激活标记和带 checksum 的 A/B 指针；失败时 live generation 不被原位覆盖，激活后通过 BroadcastChannel 让其它标签页重载。旧 SQLite 同样进入 candidate，并主动清除无法恢复的附件索引。设置页改为可键盘聚焦的原生文件入口，文案只承诺“交给浏览器下载”，材料页也补上真实删除与文件清理闭环。
- 测试：格式层 48 项覆盖 Unicode、多附件、同长度合法 JSON 篡改、SQLite 身份伪造、段 hash、严格字段及 2 GiB/1000 文件边界；恢复计划 9 项覆盖精确 key 集合、文件名/MIME/大小、零附件、重复/交叉 key 与事务回滚；代际导入 5 项覆盖坏指针回退、首次 legacy baseline、stage 失败、激活与 Vocab 隔离。连同 AI 与本地存储契约共 70 项全部通过，Career/全量 ESLint、TypeScript 与五环境 production build 通过。319×734 真实浏览器完成无附件导出，并通过原生 file chooser 上传一个末字节被篡改、包含 Unicode 材料的备份；界面明确报告附件 SHA-256 不匹配，随后“活跃机会”仍为原来的 6，证明损坏文件在写入前被拒绝。由于当前连接浏览器无法创建安全隔离 origin，未用有效测试备份替换主 origin 的真实资料；有效多附件 round-trip 由格式、事务与代际测试覆盖，并保留为发布前独立浏览器 profile 的人工演练项。
- 结果：通过。完整备份现在带走真正的材料原件，恢复从“尽力回灌”升级为可验证、可回退的代际切换；对用户可见的下载、明文与旧版限制都保持诚实。
- 下一轮候选：联系人详情、显式职位关联与真实沟通记录。

## 迭代 12 · 联系人不是销售漏斗，只记录真实关系

### 体验证据

- 任务：新增一位联系人，回看与他的职位关系、最近一次真实交流和下一步，再尝试修改或归档。
- 观察：当前卡片只有姓名、公司、手填时间和“创建待办”。新增表单允许填写“最近联系”，却没有任何沟通内容作为证据；“创建待办”还会按公司名暗中关联第一个职位。同公司有多个岗位时可能关联错误，联系方式保存后也没有详情入口。
- 影响：界面看似完整，实际把无证据时间展示成真实联系，把系统猜测展示成用户选择；红色过期跟进又把私人关系做成催促型 CRM。它既不可靠，也不照顾求职过程中的心理感受。

### 迭代产品稿

- 目标：联系人页只回答“这个人是谁、与哪些职位明确相关、真实发生过什么沟通、我是否主动安排了下一步”。不增加关系评分、回复率、冷却天数、联系频率 KPI 或失联提醒。
- 列表：导航与页面统一称“联系人”。卡片展示最多两个明确职位关联、最近一条真实联系和最早一条联系人待办；没有记录时写“等一次真实沟通”，没有待办时写“没有安排下一步”。原计划已过时只说“可重新安排”，不使用红色欠债语义。联系人与已归档分段不显示数量。
- 详情：具名卡片打开详情抽屉，首要动作是“记录联系”，其次是编辑。抽屉依次呈现下一步、明确职位关联、真实联系时间线与联系方式；邮箱和电话只打开系统应用，绝不自动写一条联系记录。空时间线明确“不需要为了填满而补写”。
- 记录联系：发生时间、渠道、方向、摘要和关联职位均由用户核对；摘要必填。可选“顺手安排下一步”，联系记录、显式职位关联与联系人待办在一个事务内保存，任一步失败都不留下半条数据。
- 编辑与归档：新增/编辑只管理基本资料和显式多选职位，不再填写“最近联系 / 下次跟进”。归档保留历史、关联与待办，支持即时撤销和从已归档恢复；本轮不提供永久删除。
- 兼容：数据库升级到 v2，但不把旧 `last_contact_at` 冒充联系记录，也不把旧 `next_follow_up` 自动生成任务。旧时间只作为待确认历史提示，由用户决定是否补录或转成待办；职位里的旧 `contact_name` 只标作旧版备注，绝不按姓名或公司自动匹配。
- Apple UI 收尾：修复透明文件入口焦点环、移动侧栏的焦点进入/圈定/归还、背景 inert、滚动锁和 Escape；“更多”真正打开完整导航。统一功能灰字对比度与 44px 热区，移除设置锚点永远高亮第一项的假状态；有 0 个逾期待办时也不再用责备式表述。
- 验收标准：新建联系人不会产生“今天联系过”；同公司两个职位只关联用户明确选择的一项；联系记录与可选待办原子写入；点击邮箱/电话不改变数据库；归档恢复不丢任何历史；v1→v2 不新增伪记录；319×734 下详情、表单、职位多选与固定操作区无溢出，键盘可完成全部闭环。
- 本轮不做：不自动发消息，不读取 LinkedIn/BOSS 登录态或站内消息，不根据公司猜职位，不永久删除联系人，不用 AI 猜测关系质量。

### 开发与验证

- 改动：Career canonical schema 升级到 v2，新增显式联系人—职位关系、真实沟通记录和带 `contact_id` 的待办；创建、编辑、互动、可选下一步、归档与恢复统一进入 Career Web Lock 和事务。v1/v2 备份都可在 candidate generation 内迁移并严格复检；旧最近联系、旧提醒和职位自由文本不会生成伪互动、伪待办或伪关系。联系人导航、列表、详情、记录联系、安排下一步、编辑和归档恢复完成独立 Apple 风格界面；职位详情增加真实关系回链，未确认文本明确标成“旧版联系人备注”。首页删除重复的第二个 AI 准备入口，避免功能越多越打扰。
- 测试：新增 18 项联系人事务、迁移和锁契约，连同备份、代际恢复、AI 与本地存储共 79 项全部通过；Career scoped ESLint、全量 TypeScript 与五环境 production build 通过。319×734 真实浏览器只读验收 3 位既有联系人：v1→v2 后没有凭空出现互动、关系或任务；列表、已归档空状态、详情、真实联系表单、可选下一步和职位详情均无横向溢出。嵌套表单打开后上一层抽屉被 inert，关闭后焦点回到“记录联系”；再关闭详情后焦点回到原联系人卡，页面滚动锁被清理。主 origin 未写入测试联系人；写入/回滚由独立 SQLite 测试覆盖，避免污染用户资料。
- 结果：通过。联系人从手填时间卡片变成有证据、可回看、可撤销的私人关系记录；界面不统计关系价值、不催促跟进，也不把系统猜测包装成用户事实。
- 下一轮候选：冻结职迹，切换到拾词的真实阅读与播客闭环验收。

## 迭代 13 · 拾词只记录真实发生的学习

### 体验证据

- 任务：以第一次打开拾词的用户身份浏览首页、文章、播客、点词解释、复习与设置，再检查这些界面承诺的数据是否真的可恢复、可撤销且符合隐私开关。
- 观察：新数据库会自动写入样例文章、播客、单词、今日复习次数与学习时长，首页却把它们呈现为个人历史；“完整备份”只带 SQLite，不带 OPFS 音频；本地锁开启后远程播放器仍会请求媒体；有字幕时勾选转写仍会上传；点 A 后立刻点 B，A 的迟到解释可能覆盖并保存到 B。每日新词上限没有进入队列，已掌握的词仍会复习，撤销评分不撤销统计；文章进度、书签、播客续播与收听时间也没有对应界面所暗示的真实性。
- 影响：这些问题不是功能少，而是用户无法区分自己的行为与演示数据，也无法相信隐私开关和备份。再增加 streak、目标环或更多统计只会放大压力和不确定性。

### 迭代产品稿

- 目标：把拾词收敛成一间私人英文阅读与听读室：点击语境中的词即可理解，愿意时再保存和复习；没有虚构历史、没有欠账、没有失真的隐私或恢复承诺。
- 方案：全新 profile 保持个人数据为零；文章与播客记录真实位置、可见阅读时间和实际播放时间；一次点词自动解释，并用请求身份与取消机制阻止串词。英文解释优先，中文按需获取；异常模型结构不入库。复习采用同一纯函数生成预告和实际到期时间，旧卡优先、每日上限只约束新卡，已掌握/忽略会暂停，撤销同时恢复卡片与统计。
- 数据边界：给当前 runtime 表建立正式 application id / user version 与版本化迁移；所有 Vocab 读写、文件、导出与恢复进入同一 Web Lock。`.vocab-backup` 必须同时包含 SQLite、所有被引用的本地音频、manifest 与逐段 hash，并通过不可变 generation + A/B 指针在完全验证后激活；旧 SQLite 也先 stage，不能原位覆盖。
- 隐私边界：本地锁开启时，URL、RSS、AI、转写与远程音频都不得发起请求；外部转写只有服务真实配置、用户明确选择且确实没有字幕时才可上传。设置页区分“检测到配置”“真实调用成功”和“未配置”，不以环境变量存在冒充连接可用。
- 心理体验：删除连续天数、隐藏的 18 分钟目标环、红色欠卡、正确率和完成率；改成最近真实阅读/收听、回到语境的次数与内容分布。零数据仍是一种完整状态，不评价自律。
- Apple UI：统一字阶、对比度、44px 热区与 safe-area；导入、点词、词详情、搜索和移动侧栏都具备名称、初始焦点、Tab 圈定、Escape、背景 inert、滚动锁与焦点归还；319×734 不横向溢出。
- 验收标准：全新 profile 统计全部为零；文章/播客的真实位置与时间跨刷新恢复；本地锁下远程媒体 0 请求；有字幕时转写 0 请求；A/B AI 乱序不串词；新卡上限、当地午夜、已掌握/忽略、撤销与特殊字符 cloze 通过固定时钟测试；含音频备份可完整 round-trip，任一损坏不切换 active generation；移动与键盘闭环通过。
- 本轮不做：不引入排行榜、连续打卡、词汇量评分或 AI 生成的学习表现评价；不把未配置的 DeepSeek chat 冒充语音转写；不在拾词稳定前开始健身平台开发。

### 开发与验证

- 改动：Vocab runtime 建立正式 SHCI application id、v2 user version 与严格 migration ledger；全新数据库不再写演示内容，旧样例只按固定 ID 一次性清理，并在外键安全的前提下保留真实 occurrence 与 review history。所有读写进入同一 Web Lock 并通过 BroadcastChannel 同步。SRS v2 用同一纯函数生成界面预告与实际计划：每日上限只限制新卡，已掌握/忽略及缺少有效英文解释的卡会暂停，补齐解释可恢复，撤销同时恢复卡片与统计；当地日期、特殊字符 cloze 与重复书签均有明确契约。文章记录真实阅读位置与可见时间，播客记录实际播放位置与收听秒数；无时间轴的纯文本字幕不再伪造同步时间。一次点词自动请求英文解释，严格解析模型结果，并用 AbortController、请求序号与 selection identity 防止 A/B 串词；中文解释仍按需获取。导入流程只有在确实没有字幕、服务已配置且用户主动勾选时才可能上传音频；本地锁同时阻止 URL、RSS、AI、转写与远程媒体。新增 `.vocab-backup`：SQLite 与所有真实引用的本地音频一并打包，manifest 自校验、逐段 hash、v0/v1/v2 候选迁移和 A/B generation 激活；旧 SQLite 也先 stage，并只清空无法随文件恢复的本地音频引用。设置页展示浏览器真实持久化状态，下载只承诺“已交给浏览器”，明文与旧版限制明确可见。整体补齐 Apple 风格字阶、对比度、44px 热区、safe-area、reduced motion，以及搜索、导入、点词、词详情和移动导航的焦点圈定、Escape、inert 与焦点归还。
- 测试：整仓 ESLint、TypeScript 与 vinext 五环境 production build 全部通过；128 项自动测试覆盖空白新库、v0/v1→v2、精确旧 seed 清理、真实历史保留、SRS 各评分/新词上限/当地午夜/撤销/暂停恢复/特殊字符、跨标签锁、AI 严格解析，以及完整备份的 0/1/多音频、Unicode、损坏、错库、未来版本、缺失对象、映射回滚、激活失败/响应丢失/状态不明和 Career 隔离。319×734 真实浏览器确认页面宽度始终为 319，无横向溢出；旧样例文章、播客和词条已从主 origin 消失，空资料库与空词库有完整状态。真实 DeepSeek 点词 `cyclist` 返回英文语境解释；紧接着 A→B 并关闭请求时，A 的迟到结果没有覆盖 B。搜索、移动导航与点词弹层均验证初始焦点、背景 inert、Escape 和精确焦点归还。设置页在浏览器拒绝持久化时明确显示“仍可能被清理”；无音频完整备份真实导出并报告 0 个本地音频；本地锁下转写 checkbox 被禁用且说明“不会上传音频”；健康检查只报告服务端配置且明确没有发送文章或词语。
- 结果：通过并冻结。拾词不再把演示数据、模型迟到结果、未发生的学习时间或不完整备份包装成用户事实；阅读、收听、点词、复习、隐私与恢复形成了可核对、可撤销的完整闭环。
- 下一轮候选：进入器械约束驱动的健身规划与日历产品稿；继续坚持“不评分自律、不制造欠账、计划服从真实环境”。
