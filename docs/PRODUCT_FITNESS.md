# 适练 · 器材约束优先的私人训练平台

> 工作名：适练（`/fitness`）。产品稿会随着真实体验继续演进；本文件先固定用户问题、设计边界和首版完整能力，避免落回“生成一张看似专业但现场做不了的计划表”。

## 一、产品命题

多数训练应用从“你应该练什么”开始，却不先问“你实际在哪里练、那里到底有什么”。于是计划依赖不存在的深蹲架、特定配重片、绳索附件或器械重量档位；到了现场只能临时改动作，所谓规划失去意义。

适练反过来：

1. 先建立真实场地和器材能力。
2. 再结合目标、经验、时间、身体限制与训练频率形成计划。
3. 每个动作必须能追溯到一件可用器材，或明确是自重动作。
4. 器材被占用、停用或不在当前场地时，给出同目的、同限制下的替代路径。
5. 训练记录反过来修正计划，而不是用连续天数和完成率评价用户。

## 二、产品原则

- **现实先于理论**：器材、重量增量、场地规则和时间窗口是规划输入，不是生成后才处理的备注。
- **可控先于评分**：展示下一次可做什么、哪里不适、负荷如何变化；不展示身材羞耻、断签惩罚或“训练失败”。
- **计划是可协商的**：临时换馆、器材被占、时间缩短、身体不适都能当场重排，不制造“计划被破坏”的感觉。
- **精确但不繁琐**：支持精确公斤数和附件，同时允许用器材模板、范围和批量录入快速开始。
- **本地优先**：训练、身体和场地资料存入独立 OPFS SQLite；AI 只接收用户主动选择的最小上下文。
- **独立体验**：与职迹、拾词不共享产品 UI；只共享安全的本地存储、AI 代理和备份基础设施。

## 三、核心信息架构

### 1. 今日

- 当前场地、今日可用时长、计划训练类型。
- 只突出“下一组 / 下一个动作”和预计剩余时间。
- 开始训练、快速改为短版、切换场地、记录身体状态。
- 器材冲突提示与一键替代。
- 不显示连续打卡、周完成率、卡路里惩罚或红色落后提示。

### 2. 场地与器材

支持多个场景：商业健身房、公司健身房、家、酒店、户外、旅行临时场地。

每个场地记录：

- 名称、地址/备注、开放时段、常去星期与时段。
- 拥挤度规律、器材排队倾向、是否允许占用多件器材做超级组。
- 单次可用时长、通勤缓冲、场地规则。
- 器材区域和现场照片（可选，原件存 OPFS）。
- 临时停用、维修、搬走、新增的变更记录。

器材通用字段：

- 类别、品牌/型号、数量、所在区域、可用状态。
- 对应动作模式和肌群，不只记录器材名称。
- 最小/最大负荷、标称单位、实际单位换算、增量方式。
- 是否容易被占、同类器材是否可互换、使用限制和个人备注。

器材细节模板：

- 杠铃：空杆重量、杆型、数量、最大承重、架位数量、安全杆/卡扣。
- 杠铃片：每种公斤数、每种片数、最小可组成增量；是否有微型片。
- 哑铃：最小/最大重量、固定或可调、档位列表、每个重量的对数、是否缺号。
- 绳索器械：单/双滑轮、倍率、配重片标称列表、每档增量、可用附件、滑轮高度范围。
- 固定器械：动作类别、座椅/靠背档位、最小/最大重量、每档增量、单双侧独立、个人设置记忆。
- 深蹲架/史密斯机：数量、杆重、轨迹、挂钩高度、安全限制。
- 长凳：平板/可调/上斜/下斜、数量、角度档位。
- 壶铃/药球/沙袋：可用重量列表和数量。
- 弹力带：阻力等级、长度、固定点条件。
- 自重设施：引体杆、双杠、台阶、吊环、地垫、可用空间。
- 有氧设备：跑步机/单车/划船机/椭圆机/爬楼机数量，速度、坡度、阻力范围，功率/心率能力。
- 小配件：V 把、直杆、绳索、踝带、腰带、助力带、泡沫轴等。

快速录入：

- 选择常见器材模板后只补重量范围和缺失项。
- 连续拍照或语音描述后由 AI 生成待核对清单；永远先预览再保存。
- 支持复制另一个场地并标记差异。
- 现场发现计划器材不存在时，可直接“此处没有”，同步修正规划规则。

### 3. 身体、目标与偏好

- 主要目标可多选并排序：力量、增肌、体能、心肺、健康、运动专项、体态或康复配合。
- 训练经验、熟悉动作、希望学习的动作、明确不喜欢的动作。
- 身高/体重等完全可选；不以 BMI 或体重变化作为默认成功标准。
- 伤病史、疼痛动作、活动度限制、医生/康复师建议与禁忌。
- 每次训练可用时长、希望保留的热身/拉伸时间。
- 喜欢的训练密度、组间休息、是否接受超级组、是否愿意排队。
- 睡眠、疲劳、压力与酸痛仅作为当日调整输入，不形成“准备度成绩”。

### 4. 计划

- 每周训练天数、无氧次数、有氧次数、完全休息日和可训练星期。
- 分化选择：全身、上下肢、推拉腿、躯干/四肢、专项、自定义；系统解释为什么适合当前频率。
- 每个训练日包含动作目的、器材、热身组、工作组、次数区间、RIR/RPE、休息、节奏和替代动作。
- 所有计划负荷必须能由场地的实际档位组成；例如 20kg 杠 + 现有杠铃片，或真实插片档位。
- 生成前做可执行性校验：器材缺失、重量无法组成、同一时段占用冲突、动作切换距离、计划超时。
- 支持标准版、短版、低疲劳版和拥挤时段版。
- 渐进规则考虑最小重量增量；增量过大时用次数、组数、节奏或动作变式进阶。
- 自动安排减量周只能作为建议，必须解释依据并允许关闭。

### 4A. 动作能力校准

“某个动作能做多少重量”不能脱离具体器材。能力记录必须绑定用户、动作、器材实例、计量方式、次数区间、RIR/RPE、动作幅度与节奏；同名但不同品牌的固定器械默认不可直接横向比较。

- 已知能力：录入最近稳定工作组，并标明总重量/每侧重量、是否使用助力带或弹力带。
- 引导校准：从保守重量开始，按主观余力逐组调整，随时允许停止。
- 未知能力：首周只规定次数与 RIR/RPE，不让 AI 猜测伪精确重量。
- 每条能力保留日期、来源和可信度；新记录不覆盖历史。
- 动作幅度缩短、节奏改变或辅助装备变化时，不自动判定为进步。

### 5. 日历

- 月、周、议程视图；训练、有氧、休息、测量/复盘作为不同事件。
- 拖动改期、跳过、缩短或换场地；跳过不算失败。
- 临时日程变化可重新分配本周刺激，避免相邻两天重复高疲劳肌群。
- 训练前显示所需器材清单、预计时长和场地冲突。
- 已完成训练可回看、编辑和复制；不删除原计划与实际执行差异。

### 6. 现场训练

- 大字、单手可操作的下一动作与下一组界面。
- 每组记录重量、次数、RIR/RPE、是否完成、疼痛/异常；默认沿用上一组以减少输入。
- 组间计时、热身组折叠、超级组/循环组、动作跳过和顺序调整。
- “器材被占”立即给出基于当前场地的替代动作，并说明替代了哪种运动模式。
- 杠铃配片计算器严格读取本场地的杆重和片数，不建议不存在的片。
- 固定器械保存座椅、靠背、把手档位，下次直接显示个人设置。
- 有氧记录：模式、时长、距离、配速/速度、坡度/阻力、平均/区间心率、主观强度；字段按设备能力显示。
- 意外中止时保留已完成组，不强迫补齐整堂训练。

### 7. 动作库

- 按运动模式、肌群、器材、难度、身体限制和当前场地筛选。
- 每个动作标记主/次肌群、器材与附件、关键设置、常见错误、替代关系。
- 用户可写自己的动作提示与外部视频链接；模型生成内容始终标为建议。
- 默认只推荐当前场地可执行动作；可主动切换“查看其他场地动作”。

### 8. 回顾

- 训练历史、负荷/次数/总量趋势、实际时长、动作熟练度和疼痛信号。
- 计划与实际差异用于发现器材冲突、计划过长和替代动作频率。
- 不使用连续打卡、排行榜、惩罚色、身材羞耻或单一综合分数。
- 所有图表回答一个可控问题，例如“哪天总是超时”“哪件器材经常导致替换”“哪种负荷增量太大”。

### 9. 设置与数据

- 单位 kg/lb，内部统一换算并保留录入单位。
- AI 隐私说明、模型连接状态、上下文预览与关闭 AI。
- 独立 SQLite 备份；完整备份包含场地照片等 OPFS 附件且不包含 API 密钥。
- 分阶段恢复、校验和、版本迁移与失败回滚。

## 四、关键数据模型（初稿）

- `fitness_venues`：场地、开放/拥挤规则、默认时长、状态。
- `fitness_equipment`：器材实例或同类组、数量、能力、状态、位置。
- `fitness_equipment_loads`：离散重量/阻力档位、数量和单位。
- `fitness_equipment_attachments`：附件及兼容器材。
- `fitness_venue_changes`：停用、维修、缺号和新增记录。
- `fitness_profiles`：目标、经验、时间、偏好与单位。
- `fitness_constraints`：疼痛、伤病、禁忌与适用日期。
- `fitness_exercises`：动作、模式、肌群、器材需求和指导。
- `fitness_exercise_substitutions`：替代关系、等价目的和限制。
- `fitness_capabilities`：动作 + 具体器材 + 计量方式 + 重量 + 次数 + RIR/RPE + 幅度/节奏 + 辅助装备 + 可信度的历史能力记录。
- `fitness_programs` / `fitness_program_days` / `fitness_program_items`：计划及版本。
- `fitness_calendar_events`：计划日期、场地、状态和改期来源。
- `fitness_sessions`：实际训练、时长、当日状态和备注。
- `fitness_session_exercises` / `fitness_sets`：动作顺序、实际器材、组数据。
- `fitness_cardio_entries`：设备、时长、距离、强度与心率。
- `fitness_body_notes`：可选测量、疲劳、睡眠、酸痛和疼痛事件。
- `fitness_files`：OPFS 文件引用、类型、大小、哈希和状态。

重量统一使用整数克或定点数存储，避免浮点误差；界面按用户单位显示。计划条目同时保存“为什么选这个动作”和器材需求快照，防止场地配置变化后历史记录失真。

## 五、AI 契约

### 计划生成输入

- 明确选择的场地及器材能力快照。
- 用户目标、经验、限制、偏好、每周时间表、有氧/无氧频次与计划周期。
- 最近若干次相关动作表现和用户主动勾选的身体状态。
- 严格禁止把完整数据库、无关健康记录或 API 密钥作为上下文。

### 计划生成输出

- 结构化 JSON：训练日、动作、场地器材 ID、组次、负荷规则、休息、时间预算、替代项。
- 每一项附可执行性声明；引用不存在的器材 ID、不可组成重量或违反限制时整份结果拒绝入库。
- 服务端只生成建议；客户端本地校验、展示差异、用户确认后保存。

### 其他 AI 动作

- 从器材照片/描述提取待确认清单。
- 根据训练日志解释平台期，但不做医学诊断。
- 在器材被占、时间缩短或身体不适时重排当天计划。
- 把自由文本训练笔记整理成结构化草稿。

## 六、情绪与健康安全

- 零训练、跳过、低重量和短训练都用中性语言呈现。
- 不默认计算或强调消耗热量、BMI、体重目标、连续天数和完成率。
- 疼痛与伤病输入触发“停止/降级并咨询专业人士”的安全路径；AI 不替代医生、物理治疗师或合格教练。
- 计划建议解释假设和限制；不给“最佳计划”“保证效果”等承诺。
- 回顾页优先发现执行摩擦，而不是评价意志力。

## 七、首轮关键验收

- 至少两个不同器材配置的场地可独立录入并切换。
- 计划中每个器械动作都能映射到当前场地的真实器材与可实现负荷。
- 删除/停用某件器材后，未来计划明确提示并提供可执行替代，不悄悄保留无效动作。
- 同一训练可在开始前切换场地并重新校验。
- 现场记录在刷新、关闭浏览器和服务重启后完整保留。
- 计划、实际执行与替代原因均可在日历历史中回看。
- AI 不可用时，器材录入、手动规划、训练记录和日历仍完整可用。
- 备份→新环境恢复后，场地、器材离散重量、计划、组记录和附件一致。
- 移动端主要操作 44px 触控目标；现场模式可单手操作并支持 Reduce Motion。

## 八、待真实体验验证的问题

- 精确到“每种杠铃片数量”是否在首次录入时过重，怎样用照片、模板和稍后补全降低成本？
- 商业健身房高峰时器材可用性应记录规律、实时状态，还是只记录替代偏好？
- 多场地计划应先生成一套跨场地兼容计划，还是按场地维护变体？
- 如何在不做准备度评分的前提下，让睡眠、酸痛和压力真正影响当天负荷？
- 训练中最少需要几次点击才能完成一组，同时仍保留 RIR/RPE 等有价值信息？
- 用户对器械标称重量不可信时，是否需要“相对档位”而非跨器械比较公斤数？
- 有氧与无氧放在同一天时，如何表达顺序、间隔和疲劳权衡，而不冒充医学建议？

这些问题会进入与职迹、拾词相同的持续闭环：真实体验 → 情绪与摩擦审查 → 产品稿 → 开发 → 测试 → Apple 风格视觉验收。
